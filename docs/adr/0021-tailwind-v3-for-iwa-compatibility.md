# ADR 0021 — Tailwind CSS v3 for IWA compatibility

- **Status:** Accepted
- **Date:** 2026-07-09
- **Supersedes:** [ADR 0019](0019-tailwind-utilities.md)

## Context

[ADR 0019](0019-tailwind-utilities.md) selected Tailwind CSS v4 with only its
theme and utilities layers. The IWA Components / PrimeReact stack instead
relies on Tailwind v3 conventions, including its layers and preflight. Keeping
v4 risks style mismatches with the known-good IWA setup.

The scaffold also needs Tailwind to discover utility classes shipped inside
the IWA packages under `node_modules`, which Tailwind does not scan by default.

## Decision

We use **Tailwind CSS v3** through PostCSS:

- `postcss.config.js` runs `tailwindcss` and `autoprefixer`; Vite needs no
  Tailwind-specific plugin.
- `src/styles/global.css` includes the `base`, `components`, and `utilities`
  layers. Tailwind preflight is part of the shared IWA-compatible baseline.
- `tailwind.config.js` scans application files and the IWA component/icon
  packages so their utility classes are generated.
- Design tokens remain CSS custom properties (`--border`, `--surface`,
  `--accent`, …) and are mapped through `theme.extend.colors`. Arbitrary-value
  utilities such as `bg-[var(--surface)]` remain valid when useful.
- CSS modules and Tailwind coexist: existing primitives may keep CSS modules,
  while new primitives can be Tailwind-only.

## Consequences

- IWA and application utilities are generated by one Tailwind v3 pipeline.
- New primitives such as `useCustomIcon` add no CSS files and remain easy to
  replace with IWA wrappers.
- The global Tailwind base layer can affect element defaults; visual checks are
  required when integrating legacy CSS-module components.
- If class-conflict resolution becomes necessary, `tailwind-merge` can be
  added behind `cx()`.
- Tailwind classes are part of a primitive's visual contract and may be
  asserted in component tests.

## Alternatives considered

- **Keep Tailwind v4 through `@tailwindcss/vite`.** It is not aligned with the
  known-good IWA stack and uses different configuration/layer conventions.
- **Tailwind v3 utilities without preflight.** Reduces global impact but
  diverges from the baseline expected by the IWA packages.
- **CSS modules only.** Does not generate the utilities used by IWA and adds
  boilerplate for simple local primitives.
- **Hard-code token values in Tailwind config.** Creates a second source of
  truth instead of reusing the existing CSS custom properties.
